Documents

Each piece of work is a .txworkshop document. It holds the transaction exactly as written, the chain data looked up for it, your notes, and the recipe it was built from. Save it anywhere, including iCloud Drive, and reopen it offline later.

Opening a transaction

On a new document's Overview:

  • Paste hex, base64 or a cardano-cli text envelope.
  • Open from File… or drop a file: .tx, .signed, .json, .cbor or .hex.
  • Fetch by ID… with a transaction id or an explorer link. It searches mainnet, preprod and preview, through your providers and Koios's public API.

The network

The network menu in the toolbar says which network the document is on: mainnet, preprod or preview. It picks the provider and places the validity window in time. When you open a transaction, or type addresses to build one, the app sets it from the addresses when they make it clear, and says so when they disagree.

Chain providers

Looking up inputs, validating with chain data, building and submitting need a provider. Add one in Settings › Providers, one per network.

ProviderWhat you need
KoiosNothing; an API key is optional
BlockfrostA project id for that network
Ogmios, with KupoYour server's URL, and Kupo's for faster address lookups
Yaci DevKitIts store URL, for a local devnet
Local node (Mac download)The node's socket path, for example ~/cardano/mainnet/node.socket
cardano-cli (Mac download)The socket path; the app finds cardano-cli in Homebrew, /usr/local/bin, ~/.local/bin or ~/cardano, or you give its path

API keys go in the Keychain. The node needs to be running and in sync.

Inspecting

The sidebar splits the transaction into Overview, Inputs & Outputs, Certificates & Governance, Scripts & Datums, Metadata, CBOR and CDDL. Look Up Inputs & Names on Inputs & Outputs fetches what each input spends, and saves it in the document so it works offline later.

Block explorers

The small arrow next to a transaction id, address, stake account, pool, DRep, governance action or asset opens it in your block explorer. Choose it in Settings: Cardanoscan, Cexplorer, AdaStat, DRepTalk, eUTxO, Pool PM or PoolTool. Where yours has no page for something, or no site for the network, another explorer that has one is used, and the link says which.

Validating

Validate runs the ledger's Phase 1 rules and evaluates Plutus scripts, offline, from the document's chain data. You get each problem with its cause, the budget each redeemer used, a step-by-step script trace, and what-if runs with changed data.

Building

Build starts from source addresses or UTxOs, then outputs, mints, script inputs, certificates, withdrawals, votes and proposals. Every field takes a value in any form: an address as bech32 or hex, or from an .addr or key file; a pool as pool1…, hex, a cold key or pool.json. The line under each field says what it read. Fees, collateral and script budgets are worked out for you.

Signing

  • Keys: add a recovery phrase or a key file (.skey) under Add a Signing Key…. They are kept in the Keychain on that device, and used only after Face ID, Touch ID, Optic ID or your passcode. Use test keys: this is a developer tool.
  • Ledger: over Bluetooth, or USB on the Mac.
  • Trezor: over USB on the Mac.
  • Keystone: by QR code, on iPhone and iPad.

Import a hardware account under Import a Hardware Account…. Hardware wallets sign payments, stake registration and delegation, vote delegation and withdrawals.

The app never moves funds on its own. It signs only what you confirm, and never asks for a recovery phrase except when you choose to add one.

Submitting

Sign & Submit sends the signed transaction through the document's provider and tracks it until it is confirmed on chain.
